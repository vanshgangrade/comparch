A. THEORY

#1 Why opcode + funct fields instead of only opcode? 22-1a
  • A 6-bit opcode can encode only 26=64 instructions. All R-type instrs share opcode 000000 and are told apart by the 6-bit funct → 64 more ALU ops without widening the 32-bit instruction.
  • R-type needs no 16-bit immediate, so its low bits are free for shamt+funct; I/J types need those bits for imm/address, so they get unique opcodes. Keeps all instrs 32-bit with fields at fixed positions (regularity → simple hardware).
  • Decoding becomes two-level: main decoder looks only at opcode (6 inputs); ALU decoder uses funct+ALUOp → smaller, faster control (see #10).
#2 Why is single-cycle control called a "Truth Table"? 21-1b, 22-1b

In single-cycle MIPS every instr finishes in one clock, so the control unit is purely combinational: no state/memory, its outputs (RegWrite, RegDst, ALUSrc, Branch, MemWrite, MemtoReg, ALUOp, Jump) depend only on the present inputs (opcode, funct). A combinational circuit is completely specified by listing outputs for every input combination = a truth table (one row per opcode), which is then implemented as SOP logic/PLA/ROM. (Multicycle control is an FSM → state table, not truth table.)

#3 How does the processor capture the side effects when instrs complete? 21-1c

Side effects = changes to architectural state: register file, data memory and PC. Combinational logic computes the new values during the cycle; they are captured only at the rising clock edge by state elements whose write enable is asserted: RF written if RegWrite=1 (WD3→reg A3), memory written if MemWrite=1 (WD→M[A]), PC←PC' every edge (multicycle: PCEn). Intermediate results in multicycle/pipeline are held in non-architectural registers (IR, MDR, A, B, ALUOut / pipeline regs) and committed in the write-back step.

#4 <<2 behaves as <<1 — which instrs affected? 21-1d, 22-1c, 24-1d, 25-3b
  • Shift-by-2 converts a word offset to a byte offset; used only for PC-relative/jump targets.
  • beq/bne (taken): PCBranch = PC+4 + (SignImm<<1) = PC+4+2·imm instead of 4·imm → wrong, half-word aligned address (e.g., imm=3 → PC+4+6 not PC+4+12) → fetches garbage/misaligned instr. Not-taken branch still OK (PC+4).
  • j (and jal): JTA = {PC+4[31:28], addr<<1} → 26b<<1 = 27 bits only; target ≈ half the intended address, wrong/misaligned → jumps to wrong location.
  • Same in multicycle (ALUOut←PC+SignImm<<2 in Decode; jump path). Not affected: R-type (add, sub, and, or, slt), lw, sw, addi — they don't use the shifters (lw/sw offsets are already byte offsets).

#6 Can rt be the dest for R-type (and rd for others)? 23-1a

Not advisable / no. MIPS reads registers from fixed fields: Read reg1 = rs (25:21), Read reg2 = rt (20:16) for all instrs, so the RF can be read in parallel with decoding. sw and beq must read rt as a source; if R-type wrote rt, its 2nd source would be in rd, so a mux (controlled by decoder) would be needed on Read register 2 → RF read starts only after control decode → longer critical path (+tctrl+tmux). Vice-versa (I-type writing rd) is impossible: bits 15:11 are part of the 16-bit immediate in lw/addi. Hence dest mux (RegDst) is on the write side: rt for I-type, rd for R-type.

#7 Do we need opcode in a special-purpose processor? 23-1c

No. A single-purpose processor executes one fixed algorithm; the algorithm is hard-coded in the controller FSM which directly sequences the datapath control signals each state. There is no program/instruction memory, no fetch and no decode, so no opcode. Only status inputs (e.g., comparator outputs) feed the controller. Opcode is needed only in general-purpose (programmable) processors.

#9 How are states generated: hardwired vs microprogrammed? 23-1b, 24-1b, 25-3a

Hardwired: current state kept in a state register (flip-flops, e.g., 4 bits for S0–S11). Next-state logic (gates/PLA) computes S' = f(S, opcode, Zero) and loads it at each clock edge; output logic decodes S to control signals. (Alternative: sequence counter + decoder giving timing states T0,T1,…, cleared at end of instr.)
Microprogrammed: each state = one microinstruction stored in a control ROM; the state register is the µPC (address). Next state is generated by an address-select logic chosen by the µinstr's sequencing field: (i) µPC+1 (sequential), (ii) dispatch ROM indexed by opcode (Decode/MemAdr branching), (iii) jump to 0 (fetch). Control signals are read directly from the µinstr bits. Easy to modify, slower; hardwired faster.

#10 Why two-level control (main decoder + ALU decoder)? 25-3c

Main decoder: opcode(6) → RegWrite, RegDst, ALUSrc, Branch, MemWrite, MemtoReg, Jump, ALUOp[1:0]. ALU decoder: ALUOp(2)+funct(6) → ALUControl. Benefits: (1) smaller logic: a monolithic controller would have 12 inputs (212=4096 rows) vs 26+28; (2) faster & simpler to design/verify; (3) modular: adding an R-type instr only changes the ALU decoder; ALU decoder reused in multicycle & pipeline; (4) funct only matters for R-type, so it isn't routed into the main decoder.

#11 PC enable: single vs multi-cycle? 25-3d

Yes. Single-cycle: PC has no enable — every instruction completes in 1 cycle, so PC←PC' at every clock edge. Multicycle: an instr takes 3–5 cycles and the PC (memory address, PC+4, branch target computations) must hold its value during intermediate states, so PC has an enable: PCEn = PCWrite + Branch·Zero (PCWrite in Fetch & Jump states; Branch·Zero in beq state).

#12 Why can't single-cycle use one memory for fetch + data? 25-1a

A single-ported memory has one address port and one read/write data port → only one access per cycle. Single-cycle lw/sw need instruction fetch AND data read/write in the same cycle → structural hazard (address port conflict). Fix: separate instruction memory and data memory (Harvard; split I-cache/D-cache) — or a dual-ported memory; (multicycle instead reuses one memory in different cycles with the IorD mux).

#13 Illegal control-signal combination 25-1b

e.g. RegWrite=1 with MemWrite=1 (during sw): memory is written correctly but the RF also writes Result (ALUResult = address, or garbage ReadData) into register rt/rd (whatever RegDst selects) → the source register (rt) being stored gets corrupted. Others: Branch=1 & Jump=1 (two PC sources, Jump mux overrides → wrong PC); MemtoReg=1 with MemRead=0 (writes undefined data).

#14 Methods of generating control signals in pipeline 24-1c, 25-4a
  1. Centralised (decode once in ID): same control unit as single-cycle generates all signals in ID; they travel with the instr through ID/EX, EX/MEM, MEM/WB; each stage uses its group (EX: RegDst, ALUSrc, ALUControl; MEM: Branch, MemWrite; WB: RegWrite, MemtoReg). Adv: one decoder, reuses single-cycle design, simple, consistent. Disadv: wider pipeline registers (more flip-flops, power).
  2. Distributed (decode per stage): pass opcode/funct down the pipe, each stage decodes its own signals. Adv: narrower pipeline regs. Disadv: duplicated decoders (area) and decode delay inside each stage's critical path.
  3. Microprogrammed/ROM per stage: flexible, easy to change; slower, big ROM. Hazard unit separately generates Stall, Flush, Forward signals.
#15 Can forwarded data be taken before the stage (pipeline) registers? (R-type→R-type) 23-1f

No. I1 computes its result in EX in cycle c; I2 needs it in its EX in cycle c+1. In cycle c+1 the wire before EX/MEM carries I2's own ALU output (I1's value is now in EX/MEM) → wrong data / combinational loop. Taking it in cycle c would chain ALU → forward mux → ID path in one cycle (longer clock). The pipeline register holds I1's result stable for the whole next cycle, so forward from EX/MEM (ALUOutM) and MEM/WB (ResultW) registers: ForwardAE=10 if (rsE≠0 & rsE==WriteRegM & RegWriteM), 01 if from WB.

#16 Setup & hold time; derive clock constraints 24-1g, 25-4c

Setup tsetup: min time D must be stable before the clock edge. Hold thold: min time D must stay stable after the edge. Path R1 → combinational logic → R2:
Setup: data launched at edge 0 arrives at R2 latest at tpcq+tpd; must arrive tsetup before next edge: Tc ≥ tpcq + tpd + tsetup ⇒ tpd ≤ Tc − (tpcq+tsetup) (sequencing overhead).
Hold: new data launched at the same edge must not reach R2 before thold; earliest arrival tccq+tcd: tccq + tcd ≥ thold (independent of Tc; fix by adding buffers). With clock skew: Tc ≥ tpcq+tpd+tsetup+tskew; tccq+tcd ≥ thold+tskew. (pcq/pd = propagation = max; ccq/cd = contamination = min.)

#17 128 registers & instruction set ×4 — effect on fields 22-2b, 23-5a, 24-1e

Reg fields: log2128 = 7 bits (was 5). 4× instrs → opcode 6→8 bits (and funct 6→8 if R-types also ×4).
R-type: op 8 + rs 7 + rt 7 + rd 7 + shamt 5 + funct 8 = 42 bits (+10). I-type: op 8 + rs 7 + rt 7 + imm 16 = 38 bits (+6).
If instruction must stay 32-bit: I-type imm shrinks to 32−8−14 = 10 bits (smaller constants/branch range); R-type has only 32−8−21 = 3 bits left for shamt+funct → must drop shamt/shrink funct or use more opcodes. Effects: bigger/slower RF, bigger decoder, fewer bits for constants.

#19 Cycles & CPI of loop program (single/multi-cycle) 21-2a, 23-3b

R1=0, R2=10; loop adds 2 to R1 → beq evaluated at R1=0,2,4,6,8 (not taken) and 10 (taken) ⇒ beq ×6, loop body (3 addi + j) ×5.
Instr count = 2 addi + 6 beq + 15 addi + 5 j = 28.
Multicycle (addi 4, beq 3, j 3): 17×4 + 6×3 + 5×3 = 68+18+15 = 101 cycles; CPI = 101/28 = 3.61.
Single-cycle: 28 cycles, CPI = 1 (but long clock).

#24 PC = 0x30000000: range reachable by beq 22-2c

Target = PC+4 + SignExt(imm)·4, imm 16-bit ∈ [−215, 215−1]. PC+4 = 0x30000004.
Min = 0x30000004 − 217 = 0x30000004 − 0x20000 = 0x2FFE0004
Max = 0x30000004 + (215−1)·4 = 0x30000004 + 0x1FFFC = 0x30020000
≈ ±128 KB (−32768 … +32767 instructions from PC+4), word aligned.

#25 Horizontal µprogram control-memory width 22-2d

Horizontal: one bit per control line → control field = 11 bits. Condition select for 8 status bits: log28 = 3 bits (MUX select). Next-address for 128 words: log2128 = 7 bits.
Width = 11 + 3 + 7 = 21 bits; control memory = 128 × 21 bits. (If status were also one-hot: 11+8+7 = 26.)

C. DESIGN / DATAPATH MODIFICATIONS

#29 Simple CPU (shared bus): add OR R1,R2 (AC ← R1 ∨ R2) 21-1e

(1) Min components: registers R1, R2 (if absent) with load (R1LD, R2LD) and tri-state buffers onto the bus (R1BUS, R2BUS); ALU gets an OR function (ALU_OR). Single bus ⇒ two operands can't travel together, so AC is used as temp: AC←R1, then AC←AC∨R2.

(2) Modified: ALU (OR op + ALU_OR input), control unit (decode new opcode; 7 instrs ⇒ 3-bit opcode, new states OR1, OR2, new signal equations), AC load logic, bus (R1, R2 drivers).
(3) States / µops: FETCH1: AR←PC; FETCH2: DR←M, PC←PC+1; FETCH3: IR←DR[op], AR←DR[addr]; OR1: AC←R1 (R1→bus, ALU pass); OR2: AC←AC∨R2 → FETCH1.
OR1 = IOR·T3, OR2 = IOR·T4 (IOR = opcode decoder output). R1BUS = OR1; R2BUS = OR2; ALU_OR = OR2; ALU_PASS = LD2 + OR1; ACLD = LD2 + ADD2 + AND2 + OR1 + OR2 (old terms + new); CLR seq. counter after OR2.

#30 Pipeline: hazard LW Ri,off(Rj) → SW Ri,off(Rk) 21-2b

sw needs Ri only in MEM (as write data); lw's data is ready at end of its MEM ⇒ forward MEM/WB → MEM (no stall). Add RtM (5 b) to EX/MEM and a mux before Dmem WD.
Detect (ForwardM=1): RegWriteW · MemtoRegW · MemWriteM · (WriteRegW ≠ 0) · (WriteRegW == RtM). WriteDataM' = ForwardM ? ResultW : WriteDataM.
If base Rk == Ri (address needs the loaded value in EX) ⇒ load-use stall 1 cycle: lwstall = MemtoRegE · (RsD == RtE); modify old lwstall so sw data reg doesn't stall: lwstall = MemtoRegE·((RsD==RtE) + (RtD==RtE)·¬MemWriteD); StallF=StallD=FlushE=lwstall. R0 never forwarded.

#38 Memory size & memory unit for SW/SH/SB/LW/LH/LB 24-3c

Size: 32-bit byte address ⇒ 232 bytes = 4 GB = 230 words × 32 bits. Organise as 4 byte-wide banks (230×8 each); A[1:0] picks byte lane, A[31:2] picks row. For 16 byte locations: 4 banks × 4 rows × 8 b, row = A[3:2].

WE[3:0] (MemWrite=1): SW → 1111; SH → A[1]=0: 0011, A[1]=1: 1100; SB → one-hot of A[1:0] (2:4 decoder). Reads: LW = word; LH = SExt16(half sel. by A[1]); LB = SExt8(byte sel. by A[1:0]). Control from opcode: Size[1:0] (00 W, 01 H, 10 B), MemWrite, MemRead.
Components & sizes (full 32-bit): 4 banks of 230×8; row decoder 30→230; 2:4 decoder + gates for WE; write-steer 3:1 mux 32 b; read: 4:1 mux 8 b, 2:1 mux 16 b, sign-ext 8→32 & 16→32, 3:1 mux 32 b. (16-loc version: 4 banks 4×8, 2→4 row decoder.)

#39 Even number of 1s detector + testbench (Verilog) 23-4

Moore FSM, 2 states: EVEN (out 1, reset/start state) and ODD (out 0); input 1 toggles state, input 0 keeps it. So output = 1 at the start (zero 1s = even).

module even_ones(input clk, rst, x,
                 output reg y);
  parameter EVEN = 1'b0, ODD = 1'b1;
  reg state, next;
  always @(posedge clk or posedge rst)
    if (rst) state <= EVEN;
    else     state <= next;
  always @(*) begin
    case (state)
      EVEN: next = x ? ODD  : EVEN;
      ODD : next = x ? EVEN : ODD;
    endcase
    y = (state == EVEN);   // 1 at start
  end
endmodule

module tb;
  reg clk = 0, rst = 1, x = 0;  wire y;
  even_ones dut(clk, rst, x, y);
  always #5 clk = ~clk;
  initial begin
    $monitor("%0t x=%b y=%b", $time, x, y);
    #12 rst = 0;
    x = 1; #10 x = 0; #10 x = 1; #10 x = 1;
    #10 x = 0; #10 x = 1; #10 $finish;
  end
endmodule
